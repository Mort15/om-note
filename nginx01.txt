#差异environment;bashrc;profile;
文件路径               | 生效范围   | 是否支持$扩展 | 加载时机
----------------------|-----------|-------------|---------------------------
~/.bashrc             | 当前用户   | 是          | 交互式非登录终端
~/.profile            | 当前用户   | 是          | 登录Shell（兼容性最好）
~/.bash_profile       | 当前用户   | 是          | 登录Shell（优先于.profile）
~/.bash_login         | 当前用户   | 是          | 登录Shell（优先于.profile，次于.bash_profile）
/etc/profile          | 所有用户   | 是          | 系统全局登录Shell
/etc/bash.bashrc      | 所有用户   | 是          | 系统全局Bash交互式终端
/etc/profile.d/*.sh   | 所有用户   | 是          | 登录Shell（推荐拆分脚本）
/etc/environment      | 所有用户   | 否          | 系统启动/登录（语法严格）
~/.pam_environment    | 当前用户   | 否          | PAM登录（极少用，语法严格）

listen 80 default_server 和 listen 80 的区别
第一个被加载的 server 块，是default_server。
或者用default_server手动指定默认。

加default_type text/plain;，不继承上层块。
如果没有可以继承的default_type，那么默认就是text/plain

为什么是text/plain？
text是大类
plain是text当中没有任何元数据的纯文本。
plain还有一层隐含语义:“这份内容是给人眼直接阅读的”。
plain老老实实把字符打印出来，千万别解析
application/octet-stream 别打开，直接让用户下载保存

location ~ .*\.(html|js|css|png)$ {
	expires 1000; #缓存1000秒

	add_header Cache-Control no-store; #主动设置，不缓存，每次都是新数据，有很多选项

# nginx不缓存，常用做一些经常变动的数据
proxy_no_cache $cookie_nocache $arg_nocache $arg_comment; #不缓存
proxy_cache_bypass $cookie_nocache $arg_nocache $arg_comment; #依旧缓存，但是不从缓存里获取数据

log_format params123 $cookie_nocache | $arg_nocache | $arg_comment; 
# $cookie_nocache 这里是cookie当中nocache字段
# $arg_nocache 这里是arg当中nocache字段
# arg就是url?age_arg1=123&age_arg2=321;
# $arg_commnet 这里是arg当中的comment字段
# 而这个 | 不会被解析，只是纯粹的装饰
upstream backend {
	server 192.168.200.146:8080;
}
server {
	listen 8081;

		access_log logs/access_params.log params123;

		index index.html;
	}
}

#万能公式 if + 内嵌变量 +正则 + set + nginx指令

if ($request_uri ~ /.*\.js$) {#匹配/xxx.js文件，匹配成功就设置变量为1
	set $my_nocache 1;
}
#三个变量 满足一个不为0不为空 就no_cache

补充课程没说的keepalived当中LVS模块:
LVS: Linux 2.4 以后 集成内核 
安装 LVS，其实指的是安装它的管理工具 ipvsadm
sudo yum install -y ipvsadm

# IP 转发临时开启，立即生效
echo 1 > /proc/sys/net/ipv4/ip_forward
# 永久开启，写入配置文件
echo "net.ipv4.ip_forward = 1" >> /etc/sysctl.conf
sysctl -p # 重新加载配置
#内核模块是否加载
lsmod | grep ip_vs
#看 ipvsadm 是否可用
ipvsadm -L -n
LVS其实就在keepalived.conf里面配置执行后就是LVS的结果。
而ipvsadm和keepalived的共同点是:都操纵同一个内核IPVS,ipvs是lvs的核心模块
不同点:keepalived写配置文件->动态，ipvsadm手动命令->静态规则。
keepalived/ipvsadm -> lvs -> ipvs
