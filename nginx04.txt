---------------- 负载均衡 ----------------

面试题 nginx负载均衡方式: rr轮询 wrr加权轮询 ip_hash url_hash 最小连接数

proxy_pass #可以带http,走七层 ; 可以只有ip:port,走四层
七层:rewrite url转发 域名跳转
四层:ssh连接 mysql连接

proxy_next_upstream error timeout http_500 http_502 http_503 http_504; #不访问，下一个

调度算法:
#rr轮询 配置相同时轮询
upstream web01 {
	server 192.168.0.1;
	server 192.168.0.2;
	server 192.168.0.3;
}
#加权 wrr 解决配置不一致
upstream web02 {
	server 192.168.0.1 weight=5; #访问五次下一个
	server 192.168.0.2 weight=1; #访问一次下一个
	server 192.168.0.3 weight=1; #访问一次下一个
}
#ip_hash 按照ip的hash结果轮询
#效果是如果第一次找到了这一台，以后一直找这一台 
#好处坏处: 会话保持 但是负载不均衡
upstream web03 {
	ip_hash;
	server 192.168.0.1;
	server 192.168.0.2;
	server 192.168.0.3;
}
#url_hash 用不到
#最小连接数 用不到

redis 同步会话需要:
1,

2, 
   php.ini 
   session.save_handler = redis #默认是file
   session.save_path = "tcp://192.168.0.1:6379" #redis默认没有密码
   #session.save_path = "tcp://192.168.0.1:6379?auth=123456789" #如果有密码
3, 
   php-fpm.d/www.conf 
   注释php_value[session.save_handler] = files
   注释php_value[session.save_path] = /var/lib/php/session
